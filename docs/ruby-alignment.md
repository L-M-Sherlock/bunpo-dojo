# 日语注音边界

页面采用“默认按词界拆分、词内允许 mono/jukugo 分段、送假名置于注音单元外”的规则。它不要求所有汉字机械地逐字注音：熟语、专名、熟字训和当て字可以整体注音，一个词内部也可以有多个对应明确的注音分段；相邻的独立词不得仅因连续使用汉字而合成一个注音单元。这份边界与读音规则同时用于 Furifont 和原生 HTML ruby 后备显示。

依据：

- [W3C《日本语组版处理要求》3.3.1](https://www.w3.org/TR/jlreq/#usage_of_ruby)区分 mono-ruby、jukugo-ruby 与 group-ruby，并说明学习参考书通常重视汉字读音的对应关系。
- [W3C Ruby Markup](https://www.w3.org/International/articles/ruby/markup.en.html#how-long)建议在需要清楚词界、行内注音或熟语排版时，每个词使用独立的 `ruby` 元素。

例如：

- `児童館／じどうかん`、`土曜日／どようび`作为一个词整体注音。
- `読／よ＋み＋聞／き＋かせ＋会／かい`把送假名留在 ruby 外。
- `午後／ごご｜三時／さんじ`、`午前／ごぜん｜八時／はちじ｜四十五分／よんじゅうごふん`按时间语义单位拆分。
- `二十日／はつか`、`一匹／いっぴき`等特殊日期或数词量词整体保留。

## 数据与运行时

`src/data/ruby-layouts.json` 为全部在用日语字段保存显式布局；题卡正文与完整读音保持不变，因此不会使内容审核哈希失效。浏览器只读取这份布局，不运行分词器，也不推测边界。若布局缺失，页面隐藏该字段的注音，`npm run audit:ruby` 会让验证失败。

正常显示使用依据本表构建的 Furifont：每个含汉注音片段只使用与其完整 `(text, reading)` 配对对应的字体选择器。字体在加载中、加载失败或浏览器不支持字体加载 API 时，继续使用同一份边界表输出原生 `<ruby>`。字体尚未确认可用前不能删除后备注音。切换“隐藏注音”后使用普通日语字体，不能由字体的默认词典额外添加未经审核的注音。

Furifont 的适用范围仅为有显式读音的注音片段；中文界面、输入框、未注音的日语和普通假名继续使用原字体。运行时通过 CSS `salt` 选择读音，不向正文插入 variation selector 或私有区字符，因此复制、搜索、判题和保存的文字保持不变。字体内的振假名跟随正文的字重和颜色；不能再独立修改振假名颜色。

完整的构建、授权和验证说明见 [Furifont 迁移](furifont-migration.md)。

答后选项说明统一显示“活用形 ← 原形（自动词／他动词）”。原形从课程词对及选项自身的完整读音匹配，不依赖正确答案、选项顺序或解析文案；类别判断题标注题目给定的原形。`verb-option-details.mjs` 保存可识别的活用范围及少量显式消歧规则，未知或不唯一的对应会使审计失败。复合表达显示当前词对的目标动词原形；「驚かせた」保留其实际原形「驚かせる」，不强行改为词对中的「驚かす」。

`ruby-source-parts.mjs` 为生成器和审计提供同一份显示字段清单，包含答后新增的原形及其课程指定读音。生成器需在仓库根目录运行，并使用项目的 Node.js 环境读取该清单。

离线生成器使用 Sudachi C 模式提出词界候选，并以作者保存的完整读音为最终依据。数词与量词、日期及时间单位会先合并；一对多或无法唯一对齐的内容必须显式处理，生成器不得静默选取一个边界。

```sh
uv run --no-project \
  --with 'sudachipy==0.6.10' \
  --with 'sudachidict-core==20250825' \
  python scripts/generate-ruby-overrides.py

npm run audit:ruby
```

`audit:ruby` 要求正式布局与全部在用含汉字段一一对应，并检查：

- 正文与完整读音均可无损重组；
- 送假名或其他普通文字没有被包进 ruby base；
- 汉字没有遗漏注音；
- 局部读音不会从小假名、促音或长音符号开始；
- 不存在重复、陈旧或未解析布局。

生成结果是排版元数据，只能改变注音边界，不能更改日语正文、词义或作者读音。
